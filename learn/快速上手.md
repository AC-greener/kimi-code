# kimi-code 快速上手开发指南

我已经仔细阅读了这个仓库的 README、CONTRIBUTING.md 和 AGENTS.md，现在给你一份完整的“AI 带你上手 kimi-code 开发”指南。

## 一、先理解这是什么

kimi-code 是 MoonshotAI 开源的 **AI 编程 Agent CLI**，用 TypeScript 编写，运行在终端里，能读写代码、执行命令、搜索文件等。它是一个 **pnpm monorepo**，结构如下：

| 目录/包 | 职责 |
|---|---|
| `apps/kimi-code` | CLI / TUI 主应用 |
| `apps/vis` | Session 可视化调试工具 |
| `packages/agent-core` | 核心 Agent 引擎（Agent、Session、tools 等） |
| `packages/node-sdk` | 对外暴露的公开 TypeScript SDK |
| `packages/kosong` | LLM/Provider 抽象层 |
| `packages/kaos` | 执行环境、文件/进程抽象 |
| `packages/oauth` | Kimi OAuth 鉴权 |
| `packages/telemetry` | 客户端遥测 |

## 二、环境准备

```bash
# 必须满足的版本要求
node >= 24.15.0   # .nvmrc 中指定，engine-strict=true 不满足会报错
pnpm 10.33.0

# 推荐用 nvm / fnm / mise 管理 Node 版本
nvm install 24.15.0 && nvm use 24.15.0

git clone https://github.com/MoonshotAI/kimi-code.git
cd kimi-code
pnpm install
```

## 三、常用开发命令

```bash
pnpm dev:cli      # 以 dev 模式运行 CLI（最常用）
pnpm test         # 运行测试（vitest）
pnpm typecheck    # TypeScript 检查（会先 build 依赖包）
pnpm lint         # oxlint 代码检查
pnpm lint:fix     # 自动修复 lint 问题
pnpm build        # 构建所有包
```

## 四、如何让 AI 带你上手（关键策略）

这个仓库本身就是为“AI 辅助开发”而设计的，有几个关键文件你必须利用起来：

### 1. 用好 `AGENTS.md`

项目根目录有 `AGENTS.md`，这是专门写给 AI Agent 看的“项目规则说明书”。当你用 Claude、Cursor、Kimi Code 等 AI 工具开发时，**把 `AGENTS.md` 的内容贴给 AI**，它会立刻理解项目边界、代码规范和工作流要求。子目录也可能有各自的 `AGENTS.md`，要就近遵循。

### 2. 推荐的 AI 上手提问顺序

克隆代码后，直接把整个目录结构和关键文件交给 AI，按这个顺序提问：

```text
第一步：让 AI 解释架构
"请阅读 AGENTS.md 和 CONTRIBUTING.md，给我解释这个 monorepo 的模块划分和数据流"

第二步：聚焦你要改的模块
"我想理解 agent-core 里 Agent 类的工作原理，帮我梳理核心流程"

第三步：找一个 Good First Issue 动手
"GitHub Issues 里有哪些适合新人的 bug fix？帮我分析这个 issue 涉及哪些文件"

第四步：写完后让 AI 帮你做提交前检查
"帮我生成符合 Conventional Commits 规范的 commit message，并用 gen-changesets skill 生成 changeset"
```

### 3. 使用 Claude Code（强烈推荐）

这种大型 monorepo 最适合用 Claude Code 这类终端 Agent 来上手，它可以直接在本地文件系统里探索代码、运行命令、理解依赖关系，比在聊天界面粘贴代码效率高很多。

## 五、贡献前必知的规则

**不要直接开 PR，先开 Issue 讨论**（以下情况必须先讨论）：

- 新功能或用户可见的行为变更
- 超过约 100 行的重构
- 公开 API 或兼容性变更

**Commit 必须遵循 Conventional Commits**，例如：

- `feat(agent-core): add tool dedup`
- `fix(tui): correct status bar alignment`

**PR 合并前必须**：运行 `pnpm changeset` 生成版本变更记录（docs-only/test-only 可以跳过）

## 六、快速找到切入点

如果你不知道从哪里开始，推荐这个路径：

1. 先跑通 `pnpm dev:cli`，自己用一下 kimi-code CLI，感受它的功能
2. 看 `apps/kimi-code` 的入口文件，理解 TUI 是怎么启动的
3. 然后往 `packages/agent-core` 里钻，这是整个系统最核心的地方
4. 挑一个 [GitHub Issue](https://github.com/MoonshotAI/kimi-code/issues) 来实际动手

顺便一提，这个仓库既然是 AI coding agent，用它来上手它自己的代码开发也是极为合适的：`cd kimi-code && kimi`，然后直接问它“带我理解这个项目的架构”，是非常有趣的体验。
